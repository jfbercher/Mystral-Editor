# Files Modified in This Fork (vs. `upstream/main`)

This document lists every file that exists in both this fork ("Mystral Editor") and upstream `antmicro/myst-editor` but has been changed, based on `git diff upstream/main...HEAD` (merge-base comparison, so it reflects only what this fork changed since diverging, not unrelated changes made independently on upstream).

Note: at the time of writing, [keyboard_shortcuts_en.md](src/keyboard_shortcuts_en.md) and [markdownDirectives.js](src/markdown/markdownDirectives.js) also have small uncommitted working-tree edits on top of the committed history described below.

## Build, config & top-level docs

- `.gitignore` — Added entries for `Saves`, `.DS_Store`, and editor backup files (`*.css~`, `*.json~`). Objective: keep local Tauri save data and macOS/editor artifacts out of version control.
- [README.md](README.md) — Prepended a "Mystral Editor" section describing the fork's purpose (local Tauri-based editing) and listing its major additions: local file management, LaTeX/KaTeX, YAML frontmatter, BibTeX bibliography, numbering/cross-referencing, footnotes, comments, enhanced admonitions, table of contents with drag-and-drop, tabs, and theming. Objective: document the fork's scope for users/maintainers on top of upstream's original README.
- [package.json](package.json) — Adds Tauri plugin dependencies (dialog, fs, opener, process, shell, updater) and a `tauri` script; adds libraries for math (katex, markdown-it-texmath), YAML parsing (js-yaml), bibliography (bibtex-js-parser), and Python code blocks (`@codemirror/lang-python`); bumps vite, `@preact/preset-vite`, and `@codemirror/lang-markdown`; adds `cross-env` to raise Node's heap size for the build; moves `vite-plugin-node-polyfills` to devDependencies. Objective: equip the project to run as a Tauri desktop app and support the new scientific-authoring features.
- [package-lock.json](package-lock.json) — Lockfile update reflecting the dependency changes above (~3,800 insertions / ~2,900 deletions); no manual edits, just the automatic result of running the package manager.
- [vite.config.js](vite.config.js) — Registers a custom `filePlugin()` (from the new `vite-file-plugin.js`) and adds `optimizeDeps.include` for the Tauri plugin packages so Vite pre-bundles them correctly; switches `resolve(__dirname, ...)` to `resolve(import.meta.dirname, ...)` for compatibility with the newer Vite version. Objective: integrate Tauri's filesystem/dialog plugins into the dev/build pipeline.

## Core editor / state / rendering pipeline

- [src/MystEditor.jsx](src/MystEditor.jsx) — Adds a collapsible/resizable Table-of-Contents side panel, wires up `setupPreviewPopups` for reference-target preview popovers, adds in-preview anchor-link scrolling and fold-arrow click handling, switches transient styled-components props to `$`-prefixed, replaces `text.renderText(false)` with a new `text.rerender()` API, calls `options.onReady` earlier, and exports `lightTheme`. Objective: support the fork's new TOC/navigation UX and popover/fold features.
- [src/mystState.js](src/mystState.js) — Adds a `number-headers` user setting, a `getBibliographyDirectory` option and an `appKeymap` option, and replaces the plain `Map` used for `cache.transform` with a new `TransformCache` class supporting async resolution and change notification. Objective: wire the state layer to support heading numbering, bibliography lookup, and robust async-transform caching.
- [src/text.js](src/text.js) — Very large rewrite of the rendering pipeline: adds math (KaTeX), heading numbering, footnotes, bibliography/citations, reference-link/target scanning, and section-reorder/preview-popover integration; replaces the effect-driven direct `renderText` call with a debounced `scheduleRender`/`rerender` pipeline; adds collapsible-heading "fold" support with click-to-toggle; extends chunk hashing to include macro/citation/numbering/heading signatures for correct cache invalidation; tightens `sanitize()`'s allowed URI scheme regexp. Also registers `tocDirectives` and `codeDirectives` with `markdown-it-docutils`, wires the `markdownPyodide` plugin for executable code-cell rendering, and registers Python with `highlight.js` (alongside YAML) so fenced `python` blocks in the preview receive full syntax coloring. Objective: support the fork's scientific-document features while keeping chunked incremental rendering efficient and correctly cache-invalidated; add inline TOC and executable Pyodide cell support; enable Python syntax highlighting in the rendered preview.
- [src/index.html](src/index.html) — Replaced the original single-editor demo page (inline example document, directly embedded `MystEditor(...)` call) with a minimal shell adding a Content-Security-Policy for Tauri, a tabs bar for multi-document editing, and delegation of bootstrapping to the new `app.js` module. Objective: reflect the fork's move to a tabbed, Tauri-hosted desktop application instead of a single embedded web demo.
- [src/comments/ycomments.js](src/comments/ycomments.js) — Adds a `mainCodeMirrorSignal` preact signal alongside the existing `mainCodeMirror` property, set whenever `registerCodeMirror` is called. Objective: let components reactively re-render once the main CodeMirror instance becomes available, instead of relying on non-reactive property access.

## Components

- [src/components/CodeMirror.jsx](src/components/CodeMirror.jsx) — Increases inline-mode font size, restyles the fold gutter marker as a chevron, reworks inline-mode CSS, applies document updates and line-map shifts immediately instead of only after a debounce (fixing dual-pane sync), wires in new extension builder calls (completions, comments, fold keys, app keymap, code block languages), removes the `editorView`/`preview` argument from several hooks in favor of reading state off `text`, and renders `YCommentsParent` based on the new reactive `mainCodeMirrorSignal`. Objective: support inline-mode rendering rework, code intelligence, custom keymaps, and comment reliability fixes.
- [src/components/Comment.jsx](src/components/Comment.jsx) — Adjusts the vertical offset of the comment popup (`top + 40` instead of `top + 20`) to account for layout changes elsewhere; a minor positioning fix with no functional logic change.
- [src/components/Diff.jsx](src/components/Diff.jsx) — Fixes a stale-closure bug: instead of capturing `options.includeButtons.value` at mount time and restoring it on unmount (which could clobber buttons added by other effects in between), it now reads/writes via `.peek()` and removes the "discard" button by filtering on its `id`. Objective: more robust button-list management when the Diff view unmounts.
- [src/components/Preview.js](src/components/Preview.js) — Major CSS rewrite: adds a shared `FoldChevron` style, reworks admonition styling to support `<details>`/`<summary>`-based dropdown admonitions with titles, icons, and new kinds (theorem, exercise, solution), tightens list spacing, adds fold/unfold styles, and adds alignment classes for tables/figures/images. Also adds a complete highlight.js CSS theme mapping all major `hljs-*` token classes (keyword, string, comment, number, literal, title/function, class/type, params, variable, symbol, etc.) to `--tok-*` CSS custom properties, making preview code coloring fully theme-responsive alongside the editor. Objective: support enhanced admonitions with titles/dropdowns, collapsible sections, figure/table alignment, and theme-matched syntax highlighting in the rendered preview.
- [src/components/TableOfContents.jsx](src/components/TableOfContents.jsx) — Adds a `compact` display mode, heading-number display when the "number headers" setting is enabled, and full drag-and-drop reordering of sibling sections. Objective: implement numbered TOC entries and drag-and-drop reorganization of document sections.
- [src/components/Topbar.jsx](src/components/Topbar.jsx) — Adds a generic dropdown mechanism (`DropdownButtonWrapper`, `OptionsDropdown`) so topbar buttons can show a hover menu populated synchronously, asynchronously, or reactively, replacing the old CSS-only `:hover` dropdown; restyles dropdown menus/items and switches the subtitle color to a new `--editor-subtitle` CSS variable. Objective: support more flexible, data-driven topbar button menus (e.g. dynamic template/file lists).

## CodeMirror extensions

- [src/extensions/codeBlockExtensions.js](src/extensions/codeBlockExtensions.js) — Adds directive info-string normalization in the sub-editor dispatch loop: a fence info tag such as `{code-cell} python` is stripped of its `{…}` wrapper and trailing language hint to yield the bare key `code-cell`, allowing the detached sub-editor to select the correct language mode. Objective: enable CodeMirror language intelligence (completions, linting) inside `:::{code-cell}` blocks.
- [src/extensions/cursorIndicator.js](src/extensions/cursorIndicator.js) — Changes `cursorIndicator` to read the preview element lazily from `text.preview.peek()` instead of a `preview` argument captured at creation time, and guards against a missing preview. Objective: fix stale-reference bugs when the preview element is remounted (e.g. on a mode switch).
- [src/extensions/index.js](src/extensions/index.js) — Registers several new extension builder methods (`useMystCompletions`, `useMystComments`, `useFoldKeys`, `useAppKeymap`, `useCodeBlockLanguages`), adds Python as a supported code-block language, customizes the fold gutter marker DOM, adds a `programmaticFold` annotation so startup folds don't steal focus, and enables CodeMirror's built-in markdown keymap. `ExtensionBuilder.codeLanguage()` is extended to normalize directive info strings (e.g. `{code-cell} python` → Python parser, `{code-cell}` alone → Python parser) so that `:::` fenced code blocks receive correct syntax highlighting in the main editor. `syntaxHighlight` gains two additional token rules — `tags.variableName` → `--tok-property` (covers plain identifiers such as `micropip` in `import micropip`) and `tags.namespace` → `--tok-classname` (module namespaces) — completing Python token coverage. Objective: wire up the fold-marker UI, code intelligence, custom keymap options, and full Python syntax coloring for `:::` fenced code cells.
- [src/extensions/inlinePreview.js](src/extensions/inlinePreview.js) — Near-total rewrite of the Inline mode rendering engine: instead of re-rendering markdown per-syntax-node from the CodeMirror syntax tree, it now projects the same cached HTML chunks that `TextManager` produces for the Preview pane onto CodeMirror widgets keyed by source line, reconstructing list items with correct depth/markers/padding, and delegating click handling to the shared `handlePreviewInteraction` utility. Objective: make Inline mode visually and behaviorally consistent with the Preview pane while avoiding a second markdown parse pass and fixing edit reliability during undo/redo and fast typing.
- [src/extensions/syncDualPane.js](src/extensions/syncDualPane.js) — Same lazy-preview-lookup pattern as `cursorIndicator.js`: `syncPreviewWithCursor` now reads `text.preview.peek()` inside the debounced callback rather than capturing a `preview` argument at creation time. Objective: prevent stale references after the preview element changes.
- [src/extensions/trackHeadings.js](src/extensions/trackHeadings.js) — Reworks heading nesting logic (`nestHeadings`) to find the closest ancestor level rather than only `level - 1` (correctly handling skipped heading levels), strips the fold marker text from heading titles, and keeps a legacy implementation for reference. Objective: fix heading-tree construction for non-sequential heading levels, needed for accurate numbering and TOC nesting.

## Markdown processing

- [src/markdown/markdownCheckboxes.js](src/markdown/markdownCheckboxes.js) — `syncCheckboxes` now returns early when the clicked `<input>` carries no `data-line-id`. Objective: stop a click on any other checkbox in the preview — a widget rendered by a Pyodide cell, typically — from being taken for a markdown task-list item and rewriting an unrelated line of the document.
- [src/markdown/markdownDirectives.js](src/markdown/markdownDirectives.js) — Extensive rewrite adding: `titledAdmonitions` (admonitions with optional titles, `<details>/<summary>` dropdown support, icon toggling, kind detection); reworked `FigureExtended`/`FigureMd`/`TableDirective`/`ListTableExtended` directives resolving numbering/labels through a shared `refMap` instead of a per-render counter, with alignment/caption numbering support; and `numberedDirectives`/`mathDirectives` tied into the new cross-reference numbering system. Also adds `TocDirective` (exported as `tocDirectives` under the aliases `toc`, `table-of-contents`, `tableofcontents`, `contents`, `toctree`): generates an inline table of contents from the document heading tree, with optional title argument, `:depth:` limit, class/id attributes, and a `:dropdown:` option that renders the TOC as a collapsible `<details>/<summary>` block; heading numbers and explicit `(label)=` anchors are preserved in the links. Adds `CodeCellDirective` (exported as `codeDirectives` under the alias `code-cell`): emits a `.code-cell-host` placeholder `<div>` carrying the base64-encoded source, package list, and options, which `markdownPyodide.js` detects via `MutationObserver` to mount the Pyodide cell widget. Objective: implement numbered/cross-referenced figures, tables, equations, and enhanced admonitions with titles and dropdowns; add an inline document-level table of contents directive; add the `{code-cell}` directive for executable Pyodide cells.
- [src/markdown/markdownFrontmatter.js](src/markdown/markdownFrontmatter.js) — Replaces the ad hoc `---`-delimited frontmatter scanner with the shared `extractFrontmatter` helper, and adds rendering of a formatted frontmatter header block (title, subtitle, authors, date, DOI, license, venue, GitHub badge) as sanitized HTML. Objective: implement YAML-frontmatter-driven bibliographic/document metadata display.
- [src/markdown/markdownMermaid.js](src/markdown/markdownMermaid.js) — Changes the Mermaid diagram element ID generation from `Math.random()` to a deterministic id derived from the token's `data-line-id` (or content hash). Objective: make re-rendering of unchanged diagrams produce identical HTML and avoid unnecessary diagram replacement/flicker.
- [src/markdown/markdownReplacer.js](src/markdown/markdownReplacer.js) — Replaces the old placeholder-`<span>`-in-the-DOM approach to async custom transforms with a new `TransformCache` class (extending `Map`) that resolves promises into the cache and notifies subscribed listeners, decoupled from any specific DOM; adds a `mystComments` markdown-it plugin stripping `%`-prefixed lines before parsing; wires a bibliography `Cite` role into custom roles. Objective: let both Preview and the rewritten Inline mode share one caching/refresh mechanism for async transforms, and implement comment-lines and citation support.
- [src/markdown/markdownSourceMap.js](src/markdown/markdownSourceMap.js) — Changes line-id generation from `Math.random()` to a deterministic `${chunkId}-${line}` id, and updates `findNearestElementForLine` to skip elements with no layout (folded/hidden sections). Objective: cache stability for source-map ids, and fix cursor/scroll sync when sections are folded.
- [src/markdown/markdownUrlMapping.js](src/markdown/markdownUrlMapping.js) — Extends `mapToken` to also map a token's direct `src` property (used by image/figure directives) and to recurse into nested children uniformly; adds `overloadMapUrl`, wrapping a user-supplied `mapUrl` function with the shared transform cache. Objective: consistent, cached URL mapping (including async resolution of local file paths in Tauri).
